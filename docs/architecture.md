# scholarlylife 网站架构

> 版本 v1 · 2026-11-26
> 参考：ATIV Software（EventPilot，B2B 会议 App）、Adobe Dreamweaver（自助产品页）

**当前进度**：P0 已上线（`/`、`/yanxu/`、`/conference/`、`/studio/`）。
研序真实截图已补齐（模拟器示例数据，`assets/yanxu/`，可用
`scripts/capture-yanxu.sh` 重新采集）。
仍缺：`/updates`、`/cases`、场景子页与 process 页。

---

## 1. 定位

**一句话**：做科研工具和科学示意网站的小团队。

**三条业务线，三种卖法**：

| 业务线 | 产品 | 卖给谁 | 卖法 | 参考对象 |
|---|---|---|---|---|
| A. 科研工作站 | 研序 Yanxu | 研究生、博士后、导师 | 自助使用，TestFlight 公测 | **Adobe** |
| B. 学术会议 App | 会议 App（XMAS-MEL 2027 为案例） | 学会、会议组委会、高校 | 项目制定制 | **ATIV** |
| C. 交互示意网站 | 台风探秘这类科学可视化 | 实验室、期刊、博物馆、会议、科普项目 | 项目制定制 | **ATIV** |
| D. 微信小程序 | 活动报名与志愿者系统（MEL 海洋科学开放日） | 活动主办方、实验室、科普项目 | 项目制定制 | ATIV |

---

## 2. 三条设计原则

1. **一个站，两套模板。** A 线用"自助产品页"（截图 + 功能 + 上手），B/C 线用"定制服务页"（场景 + 案例 + 流程 + 联系）。
2. **每个功能配一张真实截图。** 两个参考站的共同点。没有截图的功能不写。
3. **更新即内容。** 版本迭代写成 Release Notes，是一级导航项（ATIV 和 Adobe 都这么做）。

### 导航

```
scholarlylife │ 研序  会议 App  示意网站  案例  更新 │ [联系我们]
```

- 一级只放 5 项，避免 Adobe 式巨型导航（两个产品撑不起七个栏目）。
- 产品内二级导航（研序页专用）：`概览 / 功能 / 更新 / 支持`，右侧常驻 CTA。
- 页脚按**人群**分段（学 Adobe）：`研究者 / 会议主办方 / 实验室与机构`，比按产品分更好找。

## 4. 页面模板

### T0 首页

目标：三秒说清"你们是谁、做三件事"，并把人分流。

| 顺序 | 区块 | 说明 |
|---|---|---|
| 1 | Hero | 一句话 + 三个入口按钮 |
| 2 | 三张产品卡 | 研序 / 会议 App / 示意网站，各带图标、一句定位、入口 |
| 3 | 信任条 | 数字（4 个产品 / 1,630 场报告 / 0 账号）或客户 logo |
| 4 | 精选案例 | 一条：XMAS 或台风探秘 |
| 5 | 更新预告 | 最近三条 |
| 6 | CTA | 联系我们 |

### T1 自助产品页（研序）

目标：让人装上。参考 Adobe。

| 顺序 | 区块 | 必备素材 |
|---|---|---|
| 1 | Hero | 一句价值 + **TestFlight 公测**主按钮 + 支持次按钮 + 产品图 |
| 2 | 价值主张 | 两段话：为什么需要它 |
| 3 | 功能四宫格 | **每格一张截图 + 标题 + 一段**（日志 / 文献 / 日程 / 专注） |
| 4 | What's New | 最近版本的三条更新 |
| 5 | 上手 | 三步：装 → 建课题 → 记第一条日志 |
| 6 | 隐私 | 本地优先、无账号（已有文案） |
| 7 | CTA | 公测 + 支持 |

### T2 定制服务页（会议 App / 示意网站）

目标：让人来问。参考 ATIV。

| 顺序 | 区块 | 说明 |
|---|---|---|
| 1 | Hero | 场景 + 一个案例数字 + **获取方案**主按钮 |
| 2 | 场景三卡 | 会议 App：现场 / 混合 / 海报；示意网站：教具 / 展示 / 传播 |
| 3 | 案例 | 数据 + 截图 + 一句客户的话 |
| 4 | 交付流程 | 4 步 + 周期 + 交付物清单 |
| 5 | 证言 | 组织者视角（省了多少事），不是"好用" |
| 6 | FAQ | 5–6 条：周期、报价、数据来源、维护、多端 |
| 7 | CTA | 获取方案 |

### T3 案例页

背景 → 挑战 → 做了什么 → 结果（数字）→ 截图 → 客户原话。

### T4 更新页

列表：一张图 + 分类标签 + 标题 + 三行摘要 → 详情。按产品分组，按季节命名（"2026 冬季版"）。

## 6. 需要你提供的素材

**研序**
- 6 张真实截图：日志列表、日志详情、文献/课题、日程、番茄钟、搜索
- 当前版本号 + 最近三次更新内容

**会议 App**
- 交付流程：从签约到上线几周、需要甲方提供什么
- 报价方式（按会议规模？按年？）
- 可公开的客户/会议名单

**示意网站**
- 台风探秘的背景：给谁做的、数据来源、可否公开
- 还有哪些能公开的案例（海洋开放日地图？OMEL 站点？）
- 合作方式与周期

**通用**
- 团队信息：几个人、什么时候开始做、所在地
- 对外统一联系邮箱（现在混用了 163 和 stu.xmu）

## 7. 不做

1. **不做巨型导航**——两个产品撑不起七个栏目。
2. **不做倒计时促销**——没有促销活动时，折扣条会显得廉价。
3. **不做公开定价卡**——B/C 线是项目制，A 线还没定价，放价格是给自己挖坑。
4. **不做自助建站工具**——ATIV 的 portal 是它的护城河，我们没有，不承诺。
